# From Substrate Awareness to Harness Awareness

**Status:** positioning and evidence memo for the completed ToolRoute v1.0
cohort. This is the narrative basis for analysis and manuscript development; it
does not alter the frozen protocol or raw artifacts.

## Thesis

**Execution context is a first-class input to agentic reasoning.** An agent that
sees the user task and a menu of tools but not the current state of the harness
in which it acts is operationally blind. It cannot deliberately condition its
plan on whether a route is slow, failing, rate-limited, resource-constrained,
or economically infeasible.

We call the remedy **Agent Harness Awareness**: a trustworthy feedback layer
that converts host-owned execution facts into compact, decision-ready state for
the agent. The central proposition is not that one telemetry table is a
universal solution. It is that agents should be designed to reason over their
operational world just as they reason over task semantics.

This extends the Project SCAC **Substrate Awareness** thesis. Substrate
Awareness established the static case: an agent can select a more suitable plan
when it receives the execution contract before acting. Harness Awareness is the
dynamic extension: the agent receives fresh state from the tool, runtime,
hardware, and economic layers as the trajectory evolves.

## The paradigm

```text
task + tool interface                 task + tool interface + verified harness state
---------------------                 ----------------------------------------------
semantic planning                     operationally conditioned planning
"which tool can do it?"        ->    "which feasible tool should I use now?"
```

The harness state is not advice generated by the model. It is independently
measured, normalized, freshness-labelled, and kept outside model control. Its
four intended dimensions are:

1. **Hardware:** memory, CPU, disk, processes, and optional accelerator state.
2. **Tools:** recent success, failure, latency, retry-after, and circuit state.
3. **Runtime:** deadlines, wall-clock budget, exit state, and execution policy.
4. **Economics:** context headroom, token burn, quota, rate limit, and cost.

This makes Harness Awareness a systems architecture and an agentic principle:
the harness both enforces constraints and exposes a truthful, bounded view of
the state needed to reason about them.

## What ToolRoute establishes

ToolRoute is the first empirical instance of Harness Awareness. It isolates an
operational routing decision: two functionally equivalent tools can differ in
observed latency and reliability. The model makes one independent decision from
the same task and current state under three conditions:

- **A — task/tool semantics only.**
- **B — the same telemetry-shaped envelope, but equal neutral values for both
  tools.**
- **C — truthful, fresh, host-owned monitor state.**

The B condition is essential. It separates the effect of **operationally useful
state** from the effect of a longer prompt, a table-shaped interface, or the
mere presence of technical language.

### Completed evidence

The frozen cohort contains 216 independent direct-provider decisions: 6 seeds
× 4 turns × A/B/C × 3 model families (GPT-5.6 Sol, Claude Sonnet 5, Gemini 3.7
Flash). All records are completed, finalized, and hash-audited. The table below
is descriptive; the frozen analysis plan governs formal inference.

| Condition | Decisions | Mean observable policy regret | Successful operational outcomes |
| --- | ---: | ---: | ---: |
| A | 72 | 4,826.45 ms | 47/72 (65.3%) |
| B | 72 | 4,251.54 ms | 50/72 (69.4%) |
| C | 72 | 131.12 ms | 69/72 (95.8%) |

Condition C reduces mean regret by 4,120.42 ms relative to B (96.9%) and raises
completion by 26.4 percentage points. The effect appears in every model family:

| Model | A mean regret | B mean regret | C mean regret | C completion |
| --- | ---: | ---: | ---: | ---: |
| GPT-5.6 Sol | 4,723.81 | 3,307.00 | 75.50 | 23/24 |
| Claude Sonnet 5 | 5,031.72 | 4,723.81 | 75.50 | 23/24 |
| Gemini 3.7 Flash | 4,723.81 | 4,723.81 | 242.35 | 23/24 |

The result supports a strong empirical statement: **when agent decisions are
given verified current tool-health state, frontier models route substantially
better than when given task semantics alone or a structurally equivalent neutral
table.** Three C decisions selected `wait`; they remain in the denominator and
are part of the reported result.

## Relationship to existing agent research

Harness Awareness complements rather than competes with the established
reason–act and tool-use programs.

- **ReAct** shows the value of interleaving reasoning and environment actions.
  Harness Awareness specifies a missing class of observation: measured
  operational state of the execution system, not only semantic task feedback.
- **Toolformer** treats choosing and incorporating API calls as a learned model
  capability. Harness Awareness asks what the agent should know about the
  current health and feasibility of those APIs when it chooses among them.
- **AgentBench** and **τ-bench** evaluate agents in evolving interactive
  environments. ToolRoute contributes a controlled, auditable ablation of the
  information channel between the harness and the decision maker.
- **OpenTelemetry** supplies a mature instrumentation vocabulary for traces,
  metrics, and logs. Harness Awareness turns selected, provenance-preserving
  observability facts into an explicit decision interface for agents.

This is a positioning distinction, not a claim that no prior work has ever
exposed state to an agent. The contribution is the explicit paradigm, trusted
state interface, and controlled evidence that useful harness state changes
operational action selection.

## Claims architecture

The manuscript should lead with these claims:

1. **Paradigm claim:** Agent Harness Awareness is a general design principle:
   agents should receive verified, fresh operational state from their harness.
2. **Systems claim:** SST provides a practical contract for carrying that state
   across hardware, tool, runtime, and economic dimensions while preserving
   trust boundaries and freshness.
3. **Empirical claim:** In ToolRoute, truthful tool-health telemetry produces
   large, consistent improvements over both task-only and neutral same-shape
   controls across three frontier model families.
4. **Research-program claim:** ToolRoute is the operative-routing instance of a
   broader program covering resource adaptation, deadline-aware execution,
   reliability-aware recovery, and cost-aware orchestration.

The evidence section should be forceful about what it measures. The discussion
should then show the operational settings that the architecture is intended to
address—SRE, scientific workflows, multi-tool software agents, and budgeted
automation—rather than treating them as speculative afterthoughts.

## Adversarial check: ambition without overreach

| Challenge | Why it matters | Strong response |
| --- | --- | --- |
| “C is merely a better-formatted prompt.” | A formatting effect would weaken the proposed mechanism. | B holds the envelope, field names, tool rows, and neutral values constant; the B→C contrast isolates route-relevant state. |
| “The monitor signal gives away the answer.” | A hidden recommendation would reduce this to instruction following. | C reports facts—window success, latency EWMA, error/circuit state, age—not a recommended action. The external oracle is outside model control. |
| “The benchmark is synthetic.” | The evidence must be auditable and controllable. | This is an intentional first instantiation: seeded degradation permits exact counterfactual scoring, randomized order, and a clean causal ablation. The architecture is designed for real telemetry sources such as OpenTelemetry and cgroup signals. |
| “There are only two tools.” | Real harnesses can contain many choices. | Two equivalent routes isolate operational adaptation before introducing capability, schema, or task-complexity confounds. Scaling the action set is a direct next benchmark, not a conceptual change. |
| “A few models could be idiosyncratic.” | A single-model result would be fragile. | The effect is reproduced across three independent provider/model families and six balanced seeds. |

The manuscript should not dilute the thesis. It should distinguish **the broad
principle**, **the demonstrated ToolRoute mechanism**, and **the next
instantiations**. That is the appropriate form of confident research ambition.

## Candidate paper identity

### Recommended title

**Agent Harness Awareness: Verified Operational State as a First-Class Input to
Tool-Using Agents**

### Abstract opening

> Tool-using agents commonly receive task instructions and API descriptions
> while remaining unaware of the operational state of the harness in which they
> act. We introduce Agent Harness Awareness, a closed-loop design in which
> fresh, host-verified telemetry becomes a first-class input to agent decision
> making. Across 216 direct-provider routing decisions spanning three frontier
> model families, truthful tool-health state reduced observable policy regret by
> 96.9% relative to a structurally identical neutral control and increased
> operational completion from 69.4% to 95.8%.

### Contribution list

1. Defines Agent Harness Awareness as the dynamic extension of Substrate
   Awareness and articulates a four-dimensional telemetry contract.
2. Implements a trust-separated SST interface with freshness, provenance,
   external scoring, reservation-first artifacts, and finalization hashes.
3. Introduces ToolRoute, an operational tool-degradation benchmark with
   task-only, neutral-structure, and truthful-telemetry conditions.
4. Demonstrates large cross-model improvements from verified harness state and
   establishes an extensible evaluation program for dynamic agents.
