# RetryBudget Issue Ledger

**Status:** active scenario-specific ledger. Historical v0.1 artifacts remain
preserved and are not paper evidence.

| ID | Status | Finding | Risk | Required disposition |
| --- | --- | --- | --- | --- |
| RB-001 | Fixed in v0.2 | `wait` advanced the fixed schedule and discarded pending work. | A wait result could look favorable while not representing the action's operational meaning. | A host-owned logical clock now preserves pending work, quota, and work-item identity across visible recovery. |
| RB-002 | Fixed in v0.2 | Oracle regret was binary although outcomes had distinct utilities. | The score could hide meaningful action differences and fail to reflect the declared objective. | A finite observable dynamic program now returns numeric action values and numeric regret. |
| RB-003 | Fixed for development canary | `fallback` returned high utility in v0.1. | A telemetry-blind fixed fallback policy may nearly match the oracle. | Seed-varying v0.2 calibration seeds 0--11 yield 2,007 utility for the strongest fixed policy (`always checkpoint`) versus 4,371 for the observable oracle: a 54.1% gap. Repeat on the separately frozen paper seed block before any paper cohort. |
| RB-004 | Fixed in v0.2 | `checkpoint` and `terminate` lacked a lifecycle that could make them rational actions. | Decorative actions create prompt noise and weaken the experiment. | Checkpoint now preserves declared partial-work value at a cost; terminate can recover only that host-visible value. Each is uniquely optimal in a calibration state. |
| RB-005 | Fixed for baseline; sensitivity deferred | v0.1 had no A/B/C observation model or freshness/noise/missingness calibration. | A later apparent telemetry effect could be an unmeasured prompt or observation artifact. | Baseline is explicitly zero-delay, lossless independent full checkpoints. Any non-zero delay, missingness, or corruption raises rather than silently changing the measurement model. A separate sensitivity protocol is required before claims about imperfect telemetry. |
| RB-006 | Fixed for development canary | No RetryBudget prompt, runner, manifest, issue-free calibration packet, or evaluator-defeat suite existed. | Any local or provider run would be premature. | Scenario-owned prompt/capture/authorization runner, C-only Gemini canary manifest, exact handoff, pre-request configuration checks, error/revocation records, and finalization paths are committed. It remains hard-disabled pending reviewed authorization. |
| RB-007 | Fixed before trial | An initial pseudo-random option-order implementation did not ensure each action appeared at every position over five seeds. | A claimed counterbalance could have left residual action-position confounding. | A focused test caught it; v0.2 now uses a deterministic rotation that proves five-seed position balance for every state. |
| RB-008 | Fixed before trial | A seed initially only reordered five fixed state magnitudes. | A nominal multi-seed cohort could repeat the same decision instances in a different order. | Seeded generation now varies visible deadlines, retry-after values, fallback utilities, and recovery values while retaining one unique best action per initial regime. Seed-61 has a separately retained oracle calibration. |
| RB-009 | Fixed before trial | `work_item` was emitted in the condition-C state projection although it was simulator bookkeeping. | It could provide an accidental code for a state regime rather than operational information. | It is now excluded from all model-visible C state fields while remaining in host-only records for trajectory audit. |
| RB-010 | Fixed before trial | A multi-generation paid trajectory checked authorization only once. | A revoked authorization or modified manifest could permit later unreviewed requests. | The runner re-verifies authorization immediately before every provider generation and finalizes a partial artifact on revocation. |
| RB-011 | Fixed before trial | Calibration artifacts had no terminal hash manifest. | A review could not distinguish a complete artifact from a partial write or detect later alteration. | The common G2 archive now fsyncs written JSON and writes a terminal SHA-256 finalization record. Earlier no-hash calibrations remain historical and are not the current canary calibration. |
| RB-012 | Fixed before trial | Summing per-turn dynamic-program value gaps would double-count an assumed optimal future. | A multi-step episode could overstate regret. | The primary provider-trajectory summary now records realized episode utility and oracle-episode utility; their difference is episode utility regret. Per-turn dynamic-program gaps remain diagnostics only and are never summed. |
